# CLAUDE.md

Симулятор сборки ПК на Go: пользователь собирает компьютер из деталей, видит совместимость, оценку и простые объяснения. Полное описание, схема данных и дорожная карта: `docs/PLAN.md`. Читай его перед крупными изменениями.

## О проекте и авторе

- Проект учебный и для портфолио. Автор начинает с нуля в вебе и бэкенде, поэтому объясняй каждую новую вещь простым языком и на бытовых примерах, прежде чем писать код. Иди маленькими шагами, предпочитай простой идиоматичный код, а не заумные абстракции.
- Код, о котором спросят на собеседовании (хендлеры, бизнес-логика, SQL, тесты), пишет автор, а Claude объясняет, даёт подсказки и делает ревью. Обвязку (Dockerfile, CI, конфиги) пишет Claude с пояснением каждой строки.
- Общаться на русском. Код, идентификаторы и коммиты на английском; комментарии и документация на русском.

## Стек

- Go (версия из `go.mod`), роутер `chi`, PostgreSQL через `pgx`, миграции `goose`, логирование `slog`.
- Тесты: стандартный `testing`, табличные тесты; интеграционные с PostgreSQL в Docker.
- Docker, `docker compose`, GitHub Actions, `golangci-lint`.

## Правила кода

- Деньги: только `int64` в минимальных единицах (копейки). Никогда `float64`.
- Характеристики деталей храним в `specs JSONB`, часто фильтруемые поля (тип, цена, очки) в обычных колонках.
- Архитектура: handler → service → repository, зависимости передаются через интерфейсы. Пакеты в `internal/` не должны зависеть друг от друга циклически.
- Ошибки оборачивать через `fmt.Errorf("...: %w", err)`. Не глотать ошибки.
- Всегда проверять владельца записи (`user_id`) в запросах. Пользователь не должен видеть чужие данные.
- Секреты (включая ключ API для ИИ-помощника) не коммитить. В репозитории `.env.example`, а `.env` в `.gitignore`. Для тестов только синтетические данные.
- Правила совместимости (`internal/compat`) и модель оценки (`internal/scoring`) покрываются табличными тестами, включая граничные случаи.
- Чужие бенчмарки и отзывы с сайтов массово не копируем: очки ставим сами, отзывы только от пользователей приложения.

## Команды

Заполнить по мере появления в проекте:

```bash
go test ./...              # тесты
golangci-lint run          # линтер
docker compose up --build  # запуск сервиса и БД
```

## Процесс

- Работать небольшими шагами по этапам из `docs/PLAN.md`; на каждом этапе код, тесты и обновление README.
- Не коммитить и не пушить без явной просьбы автора.
- Изменения в `main` через ветки и pull request.
