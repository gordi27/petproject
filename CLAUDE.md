# CLAUDE.md

Личный финансовый помощник на Go. Полное описание, схема данных и дорожная карта: `docs/PLAN.md`. Читай его перед крупными изменениями.

## О проекте и авторе

- Проект учебный и для портфолио. Автор осваивает Go-веб-разработку, поэтому объясняй решения коротко и по делу, предпочитай простой идиоматичный код, а не заумные абстракции.
- Общаться на русском. Код, идентификаторы и коммиты на английском; комментарии и документация на русском.

## Стек

- Go (версия из `go.mod`), роутер `chi`, PostgreSQL через `pgx`, миграции `goose`, логирование `slog`.
- Тесты: стандартный `testing`, табличные тесты; интеграционные с PostgreSQL в Docker.
- Docker, `docker compose`, GitHub Actions, `golangci-lint`.

## Правила кода

- Деньги: только `int64` в минимальных единицах (копейки). Никогда `float64`.
- Даты операций: `DATE` без времени. Расчётные периоды считаются по дням выплат пользователя, а не по календарным месяцам.
- Архитектура: handler → service → repository, зависимости передаются через интерфейсы. Пакеты в `internal/` не должны зависеть друг от друга циклически.
- Ошибки оборачивать через `fmt.Errorf("...: %w", err)`. Не глотать ошибки.
- Всегда проверять владельца записи (`user_id`) в запросах. Пользователь не должен видеть чужие данные.
- Секреты и реальные финансовые данные не коммитить. В репозитории `.env.example`, а `.env` в `.gitignore`. Для тестов только синтетические данные.
- Календарная логика (`internal/periods`, `internal/recurring`) покрывается табличными тестами, включая конец месяца, 30 февраля, високосный год.

## Команды

Заполнить по мере появления в проекте:

```bash
go test ./...              # тесты
golangci-lint run          # линтер
docker compose up --build  # запуск сервиса и БД
```

## Процесс

- Работать небольшими шагами по этапам из `docs/PLAN.md`; на каждом этапе код, тесты и обновление README.
- Не коммитить и не пушить без явной просьбы автора.
- Изменения в `main` через ветки и pull request.
